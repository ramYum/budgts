## Inventory

**Port as-is.** `.gitattributes` (LF pin on migrations); the PGlite
migration-chain test and `@electric-sql/pglite`; the `tools/db/target-safety.ts`
labels; the `server-only` alias in the integration config; the `mobile/**`
lint/tsconfig excludes; `vitest.setup.ts`'s `window` guard (merged with
main's `matchMedia ??=`); migration SQL for deletion indexes, the write guard,
the ledger, and entitlements/billing events (renumbered); account deletion
core (`src/lib/account/*`, `src/lib/supabase/admin.ts`) with its tests (only
logging changes); `src/lib/plaid/native-link-params.ts`,
`src/lib/native-links.ts`; the staging integration tests; the Maestro scaffold.

**Port with adaptation.**
- Schema: native-home's ledger, entitlements, billing events, deletion table
  and indexes on top of main's lease columns and `time_zone`. `db:generate`
  must show no diff.
- Bearer auth: read paths verify the token with `getClaims()` (local JWKS),
  like `src/lib/supabase/claims.ts`. Only account deletion keeps a network
  `getUser()`, allow-listed in the performance guardrail.
- `src/proxy.ts`: allow-list entries only for routes that exist.
- Shared domain commands (`src/lib/{transactions,accounts,budget}/commands.ts`,
  `src/lib/profile/onboarding.ts`, `src/lib/command-result.ts`) are rebuilt
  from main's current server actions; the web actions become thin adapters
  that keep `revalidateUserData()`. Onboarding requires a valid `time_zone`.
  Currency stays set-once (only while `onboarded_at` is null).
- Native data API v1 (`/api/mobile/*`): months come from
  `currentMonthKey(profile.time_zone)`; `/api/mobile/profile` accepts
  `time_zone` like `syncTimeZone`.
- Home: native-home's `home-data.ts` is not ported. The query path of main's
  `(dashboard)/page.tsx` moves into one framework-free module used by the web
  page and the mobile route. No formula changes.
- Billing, switched off: lazy `db()`, codes-only logging, no trial reminder,
  routes fail closed without secrets, `requirePremium` not wired (Phase 4),
  7-day trial, $69/year and $9.99/month.
- Plaid: Bearer-or-cookie auth on link-token/exchange/item, strict Item
  removal and the disconnect deadlock retry, sync/mapping/banks commands
  rebuilt on `syncRunner()`/`drainItemInBackground()`/`db()`,
  `setAccountImportingAction` exposed natively. `.well-known` routes 404
  while their env values are unset.
- `mobile/`: sends the device time zone at Get Started and re-syncs it on
  foreground; "today"/"this month" come from the server.

**Not ported.** The tour removal and every old-design web screen (main's
design and welcome guide win); old-design legal pages, the Settings
delete-account and subscription pages, `manage-subscription` (legal pages and
the deletion UI are Phase 1, Manage Subscription is Phase 4); CI's placeholder
`DATABASE_URL`; Resend and the trial reminder; native-home's rewrites of
CLAUDE.md, the roadmap, workflow, conventions, deploy and security docs, and
the walkthrough/tour spec edits; `mobile/CLAUDE.md`, `mobile/AGENTS.md`,
`mobile/.claude/settings.json`.

## Decisions

- **Staging was not rebuilt during the port** (it already had every ported
  table, so integration tests ran against it as is). **The owner then approved
  the rebuild, done 2026-09-28**: history now matches `0000`–`0024` exactly
  and the integration suite passes 172/172. How and why it deviated from the
  planned procedure: `docs/operations/database-migrations.md` → "Staging
  rebuild (done 2026-09-28)".
- **Production is not touched**, not even read-only.
- **The ledger migration keeps all ten tables.** The influencer tables stay
  empty and no code writes to them until the influencer phase.
- **Migration numbering:** `0019` deletion FK indexes, `0020` transactions
  account index, `0021` deletion write guard, `0022` guard allows bank
  disconnect, `0023` ledger, `0024` entitlements + billing events (no
  reminder columns). Journal `when` values strictly increase after `0018`.
